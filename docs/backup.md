# バックアップとリストア

1 台の Docker Compose で動かしているときの手順です。アップデートの前には必ずバックアップを取ります。

```sh
tools/backup.sh                          # backups/<日時>/ に保存（1 分ほどサーバーが止まる）
tools/restore.sh backups/2026-11-27T040000   # 新しいマシンで: データのないスタックに戻して起動
```

| 何を | どう取るか | なくなると |
|---|---|---|
| PostgreSQL | `pg_dump --format=custom`（`postgres.dump`） | 戻せない |
| ファイル（`storage-data`） | ボリュームをそのまま（`storage-data.tar`） | 戻せない |
| `.env`、`config/` | コピー（`env`、`config/`） | 戻せない。`TOKULY_SECRET` が違うと封印済みのデータを読めない |
| NATS（`nats-data`） | ボリューム | 処理待ちのイベントとジョブ、配達をあきらめたメッセージが消える |
| Valkey（`valkey-data`） | ボリューム | レート制限と、取り消したセッションの一覧が消える |
| ClickHouse（`clickhouse-data`） | ボリューム（`--no-analytics` で取らない） | 分析だけが空から始まる |
| Caddy（`edge-data`） | ボリューム | HTTPS の証明書を取り直す |
| Meilisearch | 取らない | リストアのあとデータベースから作り直す |

地図（`tiles-data`、`map-assets`）は起動時にダウンロードし直し、ライブの録画（`recordings`）は処理途中のものだけなので取りません。

- バックアップ中はバックエンドとデータの置き場所を止め、すべてを同じ時点でそろえます。止める前に動いていたものは、
  失敗したときも含めて最後に起動し直します。
- 取る順番はデータベース → ファイルです。データベースにあってファイルがない状態は作りません。
- `images.txt` にバックアップを取ったイメージが残ります。同じ `TOKULY_VERSION` で戻すのが確実です（新しい
  バージョンなら、起動時の `tokuly migrate` が追いつかせます）。
- マイグレーションのあとで前のバージョンのイメージに戻すことはできません（前の `tokuly migrate` が、知らない
  マイグレーションの適用済みのデータベースを拒みます）。戻すときは、アップデート前のバックアップからリストアします。
- **バックアップには秘密鍵がすべて入っています。** 作るディレクトリは所有者しか読めません。マシンの外に置くときは、
  `age` や `gpg` で暗号化してから自分で運びます（スクリプトはどこにも送りません）。

## リストア

`tools/restore.sh <ディレクトリ>` は `.env` と `config/` を戻し、ボリュームを書き戻し、データベースを戻してから
スタックを起動します。検索はワーカーが起動したあと作り直すので、少しのあいだ結果が欠けます。

すでにデータがあるスタックや、`.env`・`config/` がバックアップと違うときは止まります。いまのデータを捨てて戻すときは
`--replace` を付けます（元の `.env` と `config/` は `.env.before-restore`、`config.before-restore/` に残ります）。

## 定期的に取る

cron で毎晩取り、新しい 7 つを残す例です:

```cron
0 4 * * * cd /srv/tokuly && tools/backup.sh --keep 7 >>/var/log/tokuly-backup.log 2>&1
```

`--dir /mnt/backup` で保存先を別のディスクにできます。手順は Stack ワークフローが毎回
`tools/ci/backup-roundtrip.sh`（アカウント・ノート・画像を作る → バックアップ → データを消す → リストア → 確認）で確かめています。
