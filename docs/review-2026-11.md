## 1. アーキテクチャ

### 1.1 失敗し続けたイベントとジョブを捨てていた（修正済み）

- **根拠**：`backend/crates/core/src/events.rs`（修正前）は `max_deliver: 8`、再試行の間隔は最大 60 秒で、
  合計およそ 3 分。そのあとは `AckKind::Term` で破棄し、ログに 1 行残すだけでした。ジョブ（`jobs.rs`）も同じです。
- **影響**：PostgreSQL や Meilisearch の再起動、あるハンドラーのバグが 3 分を超えると、その間に流れていたイベントは
  二度と届きません。`identity.user.deleted`（各ドメインがその人のデータを消す合図）、通知、報酬の付与が対象です。
  アウトボックスの行は発行時に削除されるので、取り戻す元もありません。
- **対応**（`9bc9fdc6`）：
  - 再試行を約 20 分に延長（12 回、2 秒から倍々で最大 5 分。`events.rs:253`, `events.rs:338`）。
  - 最後まで失敗したもの・デコードできないものは `DEAD` ストリームに 30 日保管
    （失敗したコンシューマ名と最後のエラー付き。`backend/crates/core/src/dead_letters.rs`）。
  - 運用コマンド `tokuly dead-letters list` / `tokuly dead-letters redrive [コンシューマ名の前方一致]`。
    再送は失敗したコンシューマにだけ届きます（`Tokuly-Redrive-For` ヘッダー、`26e359ed`）。ほかのコンシューマは
    とうに処理済みで、notify と feed が処理済みのイベント ID を覚えているのは 8 日だけなので、全員に送ると
    数週間前の通知が二重に届きます。
  - テスト：`backend/crates/core/tests/dead_letters.rs`（実 NATS で、埋葬 → 一覧 → 再送 → 処理）。
- **残り**：管理画面への表示と件数のメトリクスは [#145](https://github.com/fa0311/better-tokuly/issues/145)。

### 1.2 ストリーム以外の呼び出しに期限がなかった（修正済み）

- **根拠**：`backend/crates/server/src/app.rs` は `connect.into_axum_service()` をそのまま使っており、
  connectrpc 0.9.1 の `DeadlinePolicy` は既定で何もしません（期限なし、クライアント指定は無制限）。
  Web / モバイルのクライアントは期限を指定していません。
- **影響**：応答しない相手を待つハンドラーが、タスクと DB コネクションを持ったまま残ります。逆に、
  クライアントが `connect-timeout-ms: 1` を付ければ、ハンドラーを好きな時点で中断させられます。
- **対応**（`81ba83a5`）：`TOKULY_API_REQUEST_TIMEOUT_SECONDS`（既定 120 秒）。指定のない呼び出しはこの期限、
  クライアント指定は 1 秒以上・この値以下に丸めます（`backend/crates/server/src/settings.rs:71`, `app.rs:378`）。
  ストリームは開くまでだけが対象です。
- **利用者から見た変化**：120 秒を超える単発の呼び出しは `DEADLINE_EXCEEDED` になります。チャット AI の既定の
  タイムアウトは 45 秒なので通常は影響しませんが、`chat_ai_timeout_seconds` を 120 以上にしている場合は
  こちらも上げてください。

### 1.3 安定版以降のマイグレーション方針（未対応 → [#135](https://github.com/fa0311/better-tokuly/issues/135)）

- **根拠**：`backend/README.md`「Database」は「作成中はドメインのファイルをその場で編集する」と定めています。
  サーバーは `sqlx::migrate!`（`backend/crates/server/src/app.rs:219`）でチェックサム付きで適用するので、
  適用済みのファイルが 1 文字でも変わると、既存の環境は次の `tokuly migrate` で止まります。
  README もアルファ版ではデータの互換性を保証しないと明記しています。
- **影響**：最初の安定版を出した瞬間から、いまの進め方では誰もアップグレードできません。
  番号を 100 刻みにしてある（`0600_chat.sql` の次は `0601_…`）ので、追記式に切り替える余地は最初から用意されています。
- **推奨**：安定版のタグで 25 ファイルを凍結し、以後は `NNNN+1_<domain>_<内容>.sql` を足すだけにする。
  凍結をテストで強制する（凍結済みファイルのチェックサム表と突き合わせる）。詳細は [#135](https://github.com/fa0311/better-tokuly/issues/135)。

### 1.4 バックアップとリストアがない（未対応 → [#136](https://github.com/fa0311/better-tokuly/issues/136)）

- **根拠**：リポジトリに `pg_dump`・バックアップ・リストアに触れたファイルが 1 つもありません
  （`*.md` / `*.sh` / `*.yaml` を検索）。状態は 6 か所にあります：`postgres-data`、`storage-data`（全メディア）、
  `nats-data`（処理待ちのイベントとジョブ）、`valkey-data`、`search-data`、`clickhouse-data`（`compose.yaml` の `volumes`）。
- **影響**：高校生の位置履歴・チャット・写真を預かるサービスで、ディスク 1 本の故障が全消失になります。
- **推奨**：復元に必須なのは PostgreSQL・オブジェクトストレージ・`TOKULY_SECRET` の 3 つだけ、と定義するのが要点です
  （検索は再構築、ClickHouse は分析のみ、Valkey は消えても動く、NATS は止めてから取る）。詳細は [#136](https://github.com/fa0311/better-tokuly/issues/136)。

### 1.5 アウトボックスとコンシューマの残りのリスク（未対応 → [#145](https://github.com/fa0311/better-tokuly/issues/145)）

- **順序**：リレーは `ORDER BY id … FOR UPDATE SKIP LOCKED`（`events.rs:189`）。`uuidv7()` は挿入時に決まり、
  コミット順とは一致しません。ワーカーを複数動かすとバッチも交互に入ります。「順不同で届く」は既にチェックリスト
  （項目 10）にあり、消費側はその前提で書かれています。**これ以上の順序保証を足す必要はない**という判断です。
- **リレーの速度**：1 バッチ（200 行）を 1 つのトランザクションで握ったまま、1 件ずつ JetStream の ACK を待ちます
  （`events.rs:186-228`）。遅延を測る手段（最古の未送信行の経過時間）がないので、詰まっても気づけません。
- **新しいコンシューマの開始位置**：`durable_consumer`（`bus.rs`）は配信ポリシーを指定しないので、
  新しい durable 名は `EVENTS` に残っている過去 7 日分を最初から受け取ります。新機能のコンシューマが
  1 週間前のイベントで通知を送る、といった事故の元です。既定を「これから」にし、過去分が必要なものだけ明示するのが安全です。
- **位置のファンアウト**：`backend/crates/geo/src/fanout.rs:75` は位置 1 件ごとに友達全員へ個別に publish します
  （友達の上限は 1000、`backend/crates/social/src/config.rs:8`）。オンラインの友達だけに絞る（プレゼンスは既にある）と、
  10 倍の利用者でも線形に増えません。

### 1.6 1 台構成の運用（一部修正済み）

- **ログ**（修正済み `63459551`）：Docker の既定はコンテナログ無制限でした。全サービス 10 MB × 5 に制限しました。
- **メモリ**（未対応 → [#144](https://github.com/fa0311/better-tokuly/issues/144)）：`compose.yaml` は 17 サービスにメモリ上限を 1 つも持ちません。
  Meilisearch は索引作成に既定で RAM の 2/3 まで使い（公式の設定リファレンス）、ClickHouse も物理メモリに応じて確保します。
  実測できたのは開発機のネイティブ起動だけで（Docker がない環境のため Compose での計測はしていません）、
  アイドルに近い小さなサービスは Valkey 33 MB / LiveKit 41 MB / MediaMTX 24 MB / Meilisearch 110 MB /
  ClickHouse 124 MB / RustFS 194 MB でした。4 GB のサーバーで動かすための予算表と上限値が必要です。
- **ワーカーの生存確認**：`api` と `realtime` にはヘルスチェックがありますが、`worker` にはありません（`compose.yaml`）。
  リレーが止まっても Compose は気づきません。[#145](https://github.com/fa0311/better-tokuly/issues/145) の遅延メトリクスと合わせて対応するのがよいです。

### 1.7 ドメイン境界

- **結果**：`backend/migrations/*.sql` の `CREATE TABLE` からテーブル → ドメインの表を作り、各クレートの `src/` の
  `FROM / JOIN / INTO / UPDATE / DELETE FROM` を README の依存表と突き合わせました。違反は **0 件**です。
- **直したもの**（`6ecdfdbb`）：README の依存表に、`notes` と `engagement` が実際に依存している `emoji` が抜けていました。
- **推奨**：この突き合わせは 50 行ほどのスクリプトで済むので、CI の検査にすると境界が規約ではなく仕組みになります
  （[#146](https://github.com/fa0311/better-tokuly/issues/146) に含めました）。

## 2. セキュリティ（ドメイン横断）

### 2.1 「同じ学校」のおすすめ（修正済み）

- **根拠**：`tokuly_identity::users::schoolmates`（`backend/crates/identity/src/users.rs:308`）は `school_name` の一致だけで
  候補を返し、`suggestable_among` は年齢を見ていませんでした。`school_name` は利用者が自由に入力する文字列です。
  フレンド申請は既定で誰からでも受け付けます（`backend/crates/identity/src/settings.rs:14`）。
- **影響**：大人が学校名を入力するだけで、その学校を名乗る未成年の一覧が「知り合いかも」に出て、申請を送れました。
- **対応**（`eeff5fb1`）：学校だけが共通点の候補は、同じ年齢層（18 歳未満どうし／以上どうし）に限ります
  （`backend/crates/social/src/people.rs` の `schoolmates_of_age_group`）。近くの人・Bump と同じ規則です。
  友達の友達・連絡先・招待は変えていません。年齢層はクエリの条件に入れてあります（`c6fb9c02`）：先に新しい順の
  100 人を取ってから絞ると、生徒の多い学校を名乗った大人には同じ年齢層の人が 1 人も出ませんでした。
  テスト：`a_shared_school_suggests_only_within_an_age_group`, `an_adult_at_a_big_school_still_meets_the_adults_there`。
- **利用者から見た変化**：年齢層の違う「同じ学校」の人はおすすめに出なくなります（卒業生と在校生など）。

### 2.2 アカウントなしで呼べる RPC（修正済み）

- **根拠と対応**（`88acf947`、`backend/crates/identity/src/auth_svc.rs`）：
  - `ResetPassword`：制限なし、かつトークンの確認より先に Argon2（1 回約 19 MiB）を計算していました。
    → 受け付けられるリンクかを先に確かめ（`:186`, `:823`）、アドレスごとに 1 時間 30 回。
  - `CheckHandle`：制限なし（存在するハンドルの総当たり）。→ 1 分 120 回。サインイン中（設定でハンドルを
    変えるとき）はアカウントごと、未ログインはアドレスごと（`e361ceac`。学校や携帯回線の共有アドレスで、
    登録中の誰かが他の人の分を使い切らないように）。
  - `FinishPasskeySignIn`：`Begin…` だけ制限されていました。→ 同じ 5 分 60 回（`:637`）。
- テスト：`anonymous_questions_are_limited_per_address`, `a_signed_in_handle_check_is_counted_per_account`,
  `a_reset_link_works_once`。
- アプリからの引き継ぎ（`/api/auth/handoff`、`CreateWebHandoff`、`GetAuthCapabilities`）は既存の制限のままで、
  `/api/auth/handoff` は Connect の外の HTTP ルートなので 1.2 の期限の対象外です。

### 2.3 レート制限の土台（修正済み＋未対応）

- **カウンターが期限なしで残る**（修正済み `cc6b4b02`）：`Cache::rate_limit` は `INCR` のあと別の往復で `EXPIRE` していました。
  その間にプロセスが止まると期限のないカウンターが残ります。Valkey は `noeviction` と AOF で動かしているので
  （`compose.yaml`）、そのキーの人は再起動しても制限されたままです。1 本のスクリプトにまとめ、期限のないカウンターを
  見つけたら期限を付け直します（`backend/crates/core/src/cache.rs:25`）。テスト：`backend/crates/core/tests/rate_limit.rs`。
- **全体の歯止めがない**（未対応 → [#137](https://github.com/fa0311/better-tokuly/issues/137)）：制限は RPC ごとに書く方式で、API トークンにだけミドルウェアの
  上限があります（`backend/crates/core/src/api_tokens.rs:358`）。通常のセッションと匿名の呼び出しには、
  書き忘れた RPC を守るものがありません。匿名で読める `GetProfile`・コメント一覧などが該当します。
- **失効確認は「通す」側に倒れる**：Valkey が 50 ms 以内に答えないと、失効済みのセッションを見逃します
  （`backend/crates/core/src/auth.rs:135`, `:249`）。可用性を優先した意図的な設計で、影響はアクセストークンの
  寿命（15 分）までです。スタッフ権限を持つセッションだけは「拒否」側に倒すことを勧めます（[#137](https://github.com/fa0311/better-tokuly/issues/137) に含めました）。

### 2.4 未成年の初期設定（未対応 → [#138](https://github.com/fa0311/better-tokuly/issues/138)）

15 歳で登録した直後のアカウントの状態です（`backend/crates/identity/src/settings.rs:14-50` ほか）。

| 項目 | 既定 | 評価 |
|---|---|---|
| 近くの人に表示 | オフ（未成年のみ） | 良い |
| 近くの人・Bump・フォローのおすすめ | 同じ年齢層のみ | 良い |
| フォロー | 鍵アカウント（未成年のみ） | 良い |
| DM・通話 | フレンドのみ | 良い |
| 質問箱 | 閉じている | 良い |
| 位置 | フレンドにのみ | 良い |
| 検索・連絡先照合に出る（`discoverable`） | **オン**（年齢によらず） | 要判断 |

## English summary

A whole-project review at `9e11bca5`: architecture, ecosystem and cross-domain security, with the small and
medium fixes implemented on this branch.

**Fixed here** (one commit each, with tests where code changed):

- Events and jobs a handler kept failing on were dropped after about three minutes. They are now retried for about
  twenty minutes and then stored on a `DEAD` stream for 30 days; `tokuly dead-letters list|redrive` (`9bc9fdc6`).
  A redrive reaches only the consumer the event failed in (`26e359ed`).
- Same-school friend suggestions had no age rule: an adult who typed a school's name was shown its pupils.
  School-only suggestions now stay within one age group, as part of the query (`eeff5fb1`, `c6fb9c02`).
  **Behaviour change.**
- `ResetPassword` was unlimited and hashed (Argon2) before checking the token; `CheckHandle` and
  `FinishPasskeySignIn` were unlimited (`88acf947`); a signed-in `CheckHandle` counts per account (`e361ceac`).
- The rate limiter could leave a counter without an expiry (INCR and EXPIRE were separate), locking an account
  out for good; now one script (`cc6b4b02`).
- No call had a deadline and clients could assert one of a millisecond; unary calls now get
  `TOKULY_API_REQUEST_TIMEOUT_SECONDS` (120 s), clamped to at least a second (`81ba83a5`). **Behaviour change**
  for calls longer than that.
- `url` 2.5.9 (RUSTSEC-2026-0592, a stack overflow reachable with user-supplied URLs) (`79789e81`).
- Third-party GitHub Actions pinned to commits, and a Dependabot configuration (`3eaad286`).
- Container log rotation in Compose (`63459551`); `nosniff`, a referrer policy and HSTS at the edge (`49f0332e`).
- The web realtime connection re-authenticates when the session changes (`288b0023`); the last map position is
  removed from the browser when the session ends, however it ends (`94f30c60`, `8263294f`).
- Thirteen unused catalog entries and three unused web dependencies removed (`4ec77cfa`).
- The README now says the published backend image carries a GPL-3.0-or-later FFmpeg (`6c40a3c0`), and the backend
  README's dependency table lists `emoji` for notes and engagement (`6ecdfdbb`).

**Open, with designs in appendix A** (filed as #135–#146): the migration strategy after the first stable
release ([#135](https://github.com/fa0311/better-tokuly/issues/135)), backup and restore ([#136](https://github.com/fa0311/better-tokuly/issues/136)), a global rate-limit backstop for sessions ([#137](https://github.com/fa0311/better-tokuly/issues/137)), privacy and spending
defaults for minors ([#138](https://github.com/fa0311/better-tokuly/issues/138), a product decision), rotation of `TOKULY_SECRET` ([#139](https://github.com/fa0311/better-tokuly/issues/139)), a script CSP ([#140](https://github.com/fa0311/better-tokuly/issues/140)), moving off
`chrono`, which RustSec lists as unmaintained ([#141](https://github.com/fa0311/better-tokuly/issues/141)), logic duplicated between web and mobile ([#142](https://github.com/fa0311/better-tokuly/issues/142)), web start-up
loading that grows with the number of features ([#143](https://github.com/fa0311/better-tokuly/issues/143)), a memory budget for one box ([#144](https://github.com/fa0311/better-tokuly/issues/144)), observability and
