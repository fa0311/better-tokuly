# 二つのエージェントで開発する

Tokuly は 2 つの環境のエージェントが並行して開発しています。どちらも GitHub では同じアカウントを使うので、
担当はラベルとブランチ名で分けます。連絡は issue と PR のコメントで行います。

| | Linux（リード） | Mac |
|---|---|---|
| できること | バックエンド・Web・Android（KVM のエミュレーター）・Docker | iOS（Xcode、シミュレーター）・macOS でのビルド |
| 向いている作業 | 設計・認証・お金・位置情報など判断の重いもの、レビュー | iOS の確認、小さく完結した issue（常に動いているので、すぐ着手できる） |
| ラベル | `agent:linux` | `agent:mac` |
| ブランチ | `linux/…`、`api/…`、`t3/…` | `codex/…` |

## issue

- 作業は issue から始めます。担当のラベル（`agent:*`）を付け、何が終われば完了かを本文に書きます。
- 引き受けたら最初にコメントし、止まったら `blocked` を付けて理由を書きます。
- 相手に頼みたいことは、相手のラベルを付けた issue にします。

## PR

- 作業中は **Draft** で出します。手元の確認が終わったら Ready にして `needs-review` を付けます。
- 本文には `Fixes #n` か `Part of #n`、確かめたこと、画面が変わるならスクリーンショットを書きます。
- もう一方のエージェントがレビューし、結果を PR のコメントに書きます。指摘は作者が直します。
- CI の結果は待たずにマージします。リリース前にまとめて直します。
- 公開リポジトリです。秘密情報・個人情報・手元のパスは書きません。

## 粒度

- **issue は 1 つの結果**: 1 つの PR（大きくても数個）で閉じられる大きさにします。大きなテーマは親の issue にして、
  子の issue をサブ issue として並べます。「細かい残件」のような寄せ集めは作りません。
- **PR は 1 つの関心ごと**: 1 つの issue に 1 つの PR。レビューで一度に読める大きさ（生成物とテストを除いて
  数百行まで）を目安にし、大きい機能は「共有ロジックの移動 → 機能 → テスト」のように順に出します。
  ふるまいを変えない整理（移動・改名）と、ふるまいを変える変更は別の PR にします。
- **レビューの直しは同じ PR に**: 指摘への修正は、その PR のブランチにコミットを足します。直しのための別の PR は作りません。

運用のスクリプトは `tools/agent/`、使い方は `.claude/skills/tokuly-ops/SKILL.md` にあります。
